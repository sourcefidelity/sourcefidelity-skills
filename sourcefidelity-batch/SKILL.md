# Source-use review batch

**Interpreter.** Run every script with the skill's own interpreter. Resolve it in this order: `<skill>/.venv/bin/python` on macOS or Linux, or `<skill>\.venv\Scripts\python.exe` on Windows; else the same path beside `sourcefidelity-review`, the one venv the installer builds for all three skills; else `python3.12`; else `python3` if it is 3.12 or newer. `scripts/which_python.py --json` prints the choice. If none qualifies, work in prompt-only mode and state which checks are unavailable. Below, `<python>` means this resolved interpreter.

Read [REVIEW_PROTOCOL.md](REVIEW_PROTOCOL.md) and [BATCH_ADDENDUM.md](BATCH_ADDENDUM.md) in full before starting. The protocol is the canonical review specification; the addendum defines the batch schema, thresholds, and report.

Work from a supplied papers folder and source folder. Establish a private output root outside application repositories, for example `~/Documents/source-use-reviews/batch-YYYYMMDD-HHMM/`. Process `.docx` and `.pdf` papers. Skip `*AI.pdf`, `*.docx.pdf`, Turnitin reports, and non-paper files, and record every skipped file and the reason. A `.pdf` goes through the skill's extraction layer: native text where it is usable, local OCR where it is not. Record `counts_available`, which pages OCR supplied, and any page with no usable text; a PDF page is not a printed page.

Before resolving any unsupplied work, probe the bibliographic adapters once (`health` with `probe: true`) and write `adapter_status.json`. Supplied works need no adapter: their title/copyright page is identity evidence. Probe again only before a later resolution wave, not before every group. Adapter rules are in the addendum's "Adapter pre-flight" and "Efficient pipeline".

Do not review the papers yourself. Run the addendum's efficient pipeline: `prepare_batch.py`, `prepare_source.py`, `source_registry.py`, `prepare_matched.py` (one extraction per matched supplied file), rerun `source_registry.py`, then `enrich_registry.py` (chapters), `audit_supplied.py`, `screen_uncited.py` (source-like U against never-cited references for acquisition and against cited full texts for uncited-use/misplaced-attribution candidates; abstracts are triage only; no new citation judgment; `screen_uncited_model.py emit/record` ranks only listed ambiguous candidates), `fetch_open_sources.py` (DOI/Unpaywall/OpenAlex/S2/EuropePMC/CORE, landing pages, Crossref, MDPI file host), `resolve_unsupplied.py --cjk-indexes` (uncited references are skipped unless `--include-uncited`) (J-STAGE/CiNii or KISS/RISS fallback; no CNKI/Wanfang), `make_task.py` (reusing `_work/_indexes/` content-addressed source indexes; or `audit_tasks.py` to generate and check every paper at once), then `route_claims.py` for deterministic no-evidence/reuse/gate routing (source windows and validated responses are content-addressed and reused), then a worker per paper (terse reasons ≤400 chars, contributions ≤240, no source restatement) that reads only `WORKER_CONTRACT_REVIEW.md` and its `task.json` and returns `inventory.json` and `findings.json`. If the harness can make another model call, the coordinator may emit `evidence_select.py --emit` requests for citations with windows, save one response per citation, and run `--bind` before the worker; the deterministic fallback remains when no model pass is possible. Tasks mark web citations with `window_status: web_url`; the worker must inspect the supplied URL and record the access result before judging. A citation is not left `Not Judged` merely because no PDF was supplied when its URL is readable. After each worker returns, run `record_metrics.py` with its agent ID and the paper ID; do this before `render_review.py`. The worker does not self-report time or tokens. `prepare_source.py` records the supplied file's own structure (edited-collection front matter, PDF outline, contents-page chapter entries, chapter bounds), and `source_registry.py` uses it when provider metadata is missing; a chapter in an edited collection is searched only in its range, while a chapter cited from an authored book is searched in the whole book as a form error. Run `validate_inventory.py` before assessment, `render_review.py` to produce `review.md`, `ledger.md` and `summary.json`, and `validate_batch.py` at the end. Before rendering a paper, run `recover_full_text.py queue --batch ROOT` and, for each queued occurrence whose cited source has a usable extraction, `emit` one bounded packet and have an isolated model `record` one response; `apply` adds the recovered windows and rerenders through the normal validator. Recovery records `no_relevant_full_text` when no passage survives; `--whole-source` offers a bounded longest-block fallback marked as whole-source, never as query-relevant, and never forces Supports. `apply` refuses when findings and summary disagree, so repair or rerender that paper first. For a likely other-language reference (CJK characters, a romanised title with a bracketed translation, or a translation-tool note), run `native_query.py propose`, record the proposal, and mark `native_query.py route --status completed` only after the native-script searches finish; until then the work stays unresolved rather than nonexistent. The proposal is query text, never evidence. For a Tier 2 script, pass an explicit OCR language such as `rus`, `ara`, `heb`, `hin` or `tha`; no English/Chinese fallback is assumed. For a claim whose cited source is CJK, run `query_translate.py emit` for one bounded translation request, have an isolated model `record` it, and use the translated query for retrieval only; the original CJK passage stays the evidence. The optional English gloss on a contribution is reviewer-facing. Check the sample mechanics with `acceptance_cjk.py`; do not commit sampled source files. Before the final render, run `reading_gate.py run --batch ROOT --paper PID` over every occurrence and `apply` only new A/B issues; a gate-required render uses `render_review.py --require-gate`, and a check the copy cannot support is recorded as declined with a reason. Process four or five short workers concurrently; a worker must not inspect other papers, reviews or the batch report. Retry a failed paper once in a fresh context; record `failed` or `partial` with the reason.

After every scheduled paper has a status, read only the `summary.json` files and write `batch_report.md` using the addendum template. Recompute the flags from the thresholds, compute the cohort authorship signals, rank the works still needed in `acquisition_list.md`, aggregate source-level patterns by `source_key`, and preserve the per-paper reviews as the independent artifacts. The report also carries a `Batch review metrics` section aggregated from per-paper `review_metrics`. Do not rewrite or merge individual judgments. The batch report is a later aggregate, not a replacement for the independent reviews, and not a grade or misconduct determination.

Use the addendum's scripts rather than retyping numbers: `scripts/authorship_signals.py cohort` for the S2/S3 signals, `scripts/acquisition_list.py` for the acquisition ranking, and `scripts/batch_report.py` for the report itself. After a reappraisal changes any summary, run `scripts/align_report.py --batch ROOT` to refresh only the report's Paper summary table from the current summaries; it leaves the reappraisal narrative intact.

When sources are later acquired, hand off to the `sourcefidelity-reappraise` skill, which re-assesses only the occurrences citing the newly supplied works and logs every changed judgment.

Deliver the batch report path, the acquisition list path, the per-paper review and ledger paths, and a concise statement of completeness, flags, signals, source-level patterns, and limitations. If a paper could not be reviewed, say which one and why; do not fill gaps with guesses.
