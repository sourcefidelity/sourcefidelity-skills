## 2. Acceptance rules

- Scope is **APA 7 only**. Do not add instructor glossaries, other citation styles or discipline-specific synonym lists to the core.
- A change is verified by the three suites and `scripts/check_docs.py`, plus a real-document check when the change affects extraction, retrieval or review output. Synthetic tests alone are not enough for those areas.
- Do not mark a row complete from code alone. State the command and the observed result.
- A paper with zero extracted citations or references, or with no full-text source where a content judgment is claimed, cannot be reported complete. It is `partial`/`needs_manual_review`, with the reason recorded.
- Release rows additionally require the checksum, the PowerShell check, and a working default `--check` from `main`.
- **Multilingual source acceptance.** A source-language row is not done on synthetic fixtures alone if it claims real-source support: it needs a real-source extraction, identity, retrieval and one-claim model check, and the final row needs the real batch. Machine translation may be a retrieval aid only, never evidence; a non-Latin copy is not an absence finding; romanized identity needs DOI/ISBN, a supplied copy, or an explicit map.
- Keep one canonical specification per topic. A protocol change goes in `REVIEW_PROTOCOL.md` first; the design change goes in `ARCHITECTURE.md`; only the current status and next work go here.
- If a row is blocked, do independent in-scope work and state the exact decision or access needed. Do not invent a decision to close a row.
