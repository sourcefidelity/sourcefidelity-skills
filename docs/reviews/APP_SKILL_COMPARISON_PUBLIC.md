# SourceFidelity application and skills comparison

The [SourceFidelity application](https://github.com/sourcefidelity/sourcefidelity-api) and the skills address the same review problem in different environments. The skills use local Python helpers, portable files, and a human or host agent to assess what each source establishes. The application offers patterns the skills can adopt independently. This note records the findings, proposed improvements, and how to test them. The [development plan](../PLAN.md) tracks implementation status.

## Fixes already implemented on the development branch

| Finding | Change and verification |
| --- | --- |
| The DOI resolver called open-access providers and discarded their returned URLs. An Unpaywall failure could also prevent the other providers from running. | The resolver now tries distinct URLs in provider order, continues when an individual provider fails, records the successful route, and stops after saving a PDF. Offline tests cover provider failure, duplicate URLs, and early stopping. [Resolver](../../sourcefidelity-review/scripts/resolve_dois.py) |
| The batch task could drop a member of a shared citation, merge evidence from distinct sources with the same page labels, or skip a web companion when another source had local text. The renderer could accept a contribution tied to an unrelated reference. | The task now matches each marker member separately and tracks windows and access per reference. A cited task window carries the reference, source key, text hash and offsets. The renderer checks contribution membership and, when a window ID is supplied, checks the excerpt against that window. Regression coverage includes three-source groups, ambiguous matches, same-page windows, and web companions. [Task builder](../../sourcefidelity-batch/scripts/make_task.py) · [Report validator](../../sourcefidelity-batch/scripts/render_review.py) |

## Next opportunities

### Discovery and source acquisition

- **Separate submitted identifiers from resolved identity.** An unregistered DOI or a DOI for another work should permit a bounded title-and-author lookup. Preserve the submitted DOI and its outcome even if the lookup identifies the intended work. Test a stale identifier, a valid identifier for the wrong work, and a search returning two plausible candidates. [DOI resolver](../../sourcefidelity-review/scripts/resolve_dois.py)
- **Record how each search ended.** Distinguish a completed empty result, rejected candidates, provider failure, and a route skipped for lack of time or capability. Extend that distinction to batch caches so an incomplete lookup can resume. Skip DOI lookups for metadata already cached, and share per-provider pacing and cooldown across commands. Compare request counts and outcomes with identical provider responses before measuring live latency. [Batch resolver](../../sourcefidelity-batch/scripts/resolve_unsupplied.py) · [Batch pacing](../../sourcefidelity-batch/scripts/retrieval/pacing.py)
- **Keep links, copies, and coverage distinct.** Preserve the submitted link, its observed outcome, any alternative location, and the identity and edition of the retrieved copy. Treat abstracts, previews, and partial chapters as bounded evidence. Use a common public-network fetch policy with consistent redirect checks, timeouts, and response limits before expanding automated retrieval. Test wrong editions, truncated copies, and working alternative routes that leave the submitted link outcome intact. [Source pack](../../sourcefidelity-review/scripts/sourcepack.py) · [Hyperlink audit](../../sourcefidelity-review/scripts/hyperlink_audit.py)

### Intake and evidence retrieval

- **Reuse one citation and reference inventory.** Carry the exact submitted text, paragraph and marker offsets, and reference membership across extraction, link checking, and evidence preparation. Keep ambiguous entries visible for adjudication. Inspect uncited clauses in partially cited paragraphs, with a separate outcome for possible continuation. Test wrapped bibliography entries, corporate authors, repeated markers, and titles followed by release years. [Candidate extraction](../../sourcefidelity-review/scripts/extract_candidates.py) · [Inventory validation](../../sourcefidelity-batch/scripts/validate_inventory.py)
- **Tie excerpts to the copy and extraction that produced them.** Extend the current window binding with an extraction version and options, and reuse the local text only when the copy, text, and page mapping still agree. Include chapter restrictions and distinguish a printed page from a PDF index. Test changed OCR settings, missing text artifacts, and altered page maps. [Source preparation](../../sourcefidelity-review/scripts/prepare_source.py) · [Page mapping](../../sourcefidelity-review/scripts/page_map.py)
- **Protect quotation and locator hits before changing ranking.** Retrieve exact quotations and stated locators independently, retain the original text and offsets, then try a lightweight local lexical index for supplemental passages. Compare the same sources and queries under both methods. Measure quotation and locator recall, wrong-source windows, repeated excerpts, and elapsed time. Keep a search miss visible as a coverage limitation. [Task builder](../../sourcefidelity-batch/scripts/make_task.py) · [Review protocol](../../sourcefidelity-review/REVIEW_PROTOCOL.md)

### Findings, reporting, and reappraisal

- **Add narrow, inspectable checks.** Useful candidates include quotation-locator omissions, bibliography order, and labeled quantities with explicit unit and period. Preserve the spans or fields that support each observation, and leave unclear formatting, wording, or attribution open for review. Test ordinary negatives such as titles mistaken for quotations and the right number attached to the wrong period. [Review protocol](../../sourcefidelity-review/REVIEW_PROTOCOL.md) · [DOCX formatting reader](../../sourcefidelity-review/scripts/docx_text.py)
- **Derive summaries from recorded findings.** Use stable issue identifiers linked to their citation, reference, work, or uncited passage. Count each issue type once, reconcile the report with the ledger and inventory, and align hyperlink-count guidance across the skills. Test repeated issues, uncited references, and findings that must stay provisional because search or access was incomplete. [Report renderer](../../sourcefidelity-batch/scripts/render_review.py) · [Batch validation](../../sourcefidelity-batch/scripts/validate_batch.py)
- **Make reappraisal recoverable.** Bind each proposed change to the prior report and the affected citation and source. Check that the prior artifacts still match before accepting the change. Keep the previous revision and verify that unrelated judgments survive a retry or interruption. [Reappraisal workflow](../../sourcefidelity-reappraise/REAPPRAISAL_PROTOCOL.md) · [Reappraisal writer](../../sourcefidelity-batch/scripts/reappraise_apply.py)

Prioritize reproducible identity and evidence handling before introducing heavier ranking or model dependencies. Measure completed lookups, avoided requests, extraction reuse, evidence recall, and the time spent in each stage. Keep the skills usable with local files and their existing prompt-only workflow. The proposals above are candidates for future work. The implemented fixes and their verification are recorded in the [development plan](../PLAN.md).
