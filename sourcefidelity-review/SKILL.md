# Source-use review

**Interpreter.** Run every script with the skill's own interpreter. Resolve it in this order: `<skill>/.venv/bin/python` on macOS or Linux, or `<skill>\.venv\Scripts\python.exe` on Windows; else the same path beside `sourcefidelity-review`, the one venv the installer builds for all three skills; else `python3.12`; else `python3` if it is 3.12 or newer. `scripts/which_python.py --json` prints the choice. If none qualifies, work in prompt-only mode and state which checks are unavailable. Below, `<python>` means this resolved interpreter.

**Preflight.** Start every review with `scripts/update_check.py` (silent unless an update is due; it checks at most once a week). If it prints a line, put that line at the top of the reply. Add `Instrument: sourcefidelity-review vX (commit H)` to the scope block, from `scripts/update_check.py --stamp`.

Read [REVIEW_PROTOCOL.md](REVIEW_PROTOCOL.md) in full before starting. It is the canonical review specification and can also be used without this skill.

No key is required. Free keys (Google Books, OpenAlex, Semantic Scholar, CORE)
raise provider quotas; store them once with `scripts/user_settings.py --prompt`.
To reproduce a keyless install, set `SOURCEFIDELITY_DISABLE_KEYS=1`.

Work from one original paper and the supplied source files or source folder. Establish the exact inputs and a private output location outside application repositories. Use read-only access to inputs; write only review artifacts and necessary temporary extraction/rendering files. Leave applications, stored sources, and existing reports unchanged. No API key and no MCP server are required. Resolve identity from the supplied copies first; for a work with no supplied copy, use the public Crossref endpoint or ordinary web search. Use read-only HTTP or WebFetch for full-text inspection. If a service is unavailable, record the limitation rather than the work's nonexistence.

Follow the protocol's sequence: establish independence and access, inventory the whole paper, resolve sources, review every occurrence, review the bibliography, then reconcile the audit counts. Maintain the companion audit ledger as work proceeds so a resumed review can distinguish completed inspection from pending work. Continue through the whole authorized paper rather than stopping after a sample.

Open the delivered review with the protocol's **Review scope and counts** block (word counts, occurrence/reference/work/uncited/hyperlink counts, and the report's review time and tokens), then the academic-integrity summary (Category A/B findings and the counts line), then the detailed findings. Compute total, text, and reference word counts from the original paper with `scripts/word_count.py` and format them as `Word counts: total N; text N; references N.` Deliver the Markdown review and ledger with their paths and a concise statement of completion and limitations. A structural audit is not proof of judgment accuracy. Do not claim this skill has been validated across papers merely because its instructions or file format pass validation.

For a prepared single review, record agent usage with the sibling batch skill’s `scripts/record_metrics.py --batch REVIEW_ROOT --paper paper --phase review` and the agent metadata or measured usage flags. The renderer reads the resulting sidecar. With no measured usage, the scope block says `not recorded`.

There is one report shape: the scope block, the academic-integrity summary, the citing entries, the bibliography issues, the substantive uncited statements and the limitations, plus the companion ledger. Counts, review time and tokens live in the scope block. Deliver exactly that shape: do not add a findings index, a separate formatting-notes line, or a concluding synthesis section; the review ends with the limitations section. Sourced link counts come from `scripts/hyperlink_audit.py --paper <masked docx> --out <dir>`, which classifies each link state and marks environment-caused fetch failures; retrieval and identity come from `scripts/resolve_dois.py`, whose accession record documents what was and was not retrieved.

**Identity.** Mask the student's identity before any artifact with the batch skill's `scripts/redact_identity.py --tier 2`; it clears `docProps/core.xml`, `app.xml`, `custom.xml` and thumbnail previews. Verify the masked copy before use: `hyperlink_audit.py` expects it, and no identity value may appear in `review.md`, `ledger.md` or `_work`. A residual unlabelled title block is a limitation to record, not a value to guess.

**Tool ownership.** For a single review, `hyperlink_audit.py` is this skill's link audit; `link_states.py` and `record_metrics.py` belong to the sibling batch skill. Follow the rendering step below for review artifacts. `word_count.py` accepts a singular "Reference:" heading for counting only; that heading is still a Category A defect for the review.

**Reading the paper.** Use `scripts/docx_text.py --paper FILE --out DIR`; it writes `paper-text.md` and `paper-text.json` with paragraph IDs, italic and bold runs, indentation, heading style and hyperlink targets, so article-title versus journal italics and hanging indent are checked from data. A DOCX has no printed pagination, so locators stay paragraph-based and that is a recorded limitation.

**Dossier first.** Before probing any reference, run `scripts/dossier.py --paper FILE --out DIR [--cache-dir DIR]`. It runs the resolver's identity pass and the link audit together and writes `dossier.md` and `dossier.json`, one row per reference: identity, DOI, link state, fetch detail, host state and notes. Use that table as the reference inventory; do not curl reference URLs or query Crossref, OpenAlex or CORE one reference at a time. `--no-network` parses only; `--no-fetch` resolves identity but does not request links.

**Source pack.** `scripts/sourcepack.py --paper FILE --sources DIR --out DIR` maps supplied PDFs to references, extracts each once through `prepare_source.py`, and writes `_work/sourcepack/index.md` plus `index.json`. Search the pack with `--search "phrase"` instead of re-reading PDFs; `--map R3=PATH` overrides a mapping. Adjudicate each proposed match. Check the unmapped PDFs for scans or ambiguous titles and record any confirmed match with `--map`.

**Open-access fetch.** `scripts/openfetch.py --paper FILE --out DIR` checks OpenAlex and CORE once per reference, saves public PDFs under `_work/open/<R>/` and records blocked or no-OA results. For one supplied or discovered URL, `scripts/fetch.py --url URL --out DIR` fetches it once and refuses a host already remembered as blocked (24 hours); use `--force` deliberately. After the fetch, run `scripts/ingest_open.py --root DIR --rebuild`: it stages each saved text under `_sources/<source_key>/text.txt`, records the extraction and a confirmed identity on the registry work, and reruns `make_task.py` so the task carries windows for those works. Without this step the bounded path leaves those occurrences packet-less.

**Single-paper prep for record rendering.** With the sibling batch skill installed, `scripts/one_paper.py --paper PAPER --sources SOURCE_DIR --out REVIEW_ROOT` runs the batch inventory, detects reference entries even without a reference heading or with corporate-author entries, adds author-year citations the batch extractor left in `year_mentions`, maps supplied files by author/title, extracts only the mapped files, and writes `_work/paper/task.json` plus a `prep_report.md`. It needs the sibling `sourcefidelity-batch` skill. The candidate inventory and the automatic mapping are fallible: adjudicate every candidate and override a mapping with `--map KEY=PATH`.

**Direct review (default).** After the task and inventory are prepared, review the whole paper in this conversation against the source windows and the passages you request: judge every occurrence and every reference entry, screen the uncited candidates, and record A/B findings and APA issues. Read sources in targeted excerpts and record the printed locator for each finding. Write `review.md` and `ledger.md` from the protocol, or record the adjudicated inventory and judgments with the sibling worker contract and render them with `scripts/one_paper.py --out ROOT --inventory ... --findings ...`. This is the default single-review path; on the Television benchmark it is faster and cheaper than the bounded experiment.

**Bounded per-claim path (experimental).** On request only, or for a re-adoption trial, `one_paper.py --out ROOT --bounded --inventory ROOT/paper/inventory.json` writes one request per checkpoint-pending, packet-ready claim under `_work/paper/bounded-requests/`. Answer each request from its packet alone (a worker or subagent per claim), write each response to `_work/paper/bounded-responses/<claim_id>.response.json` under the batch `BOUNDED_WORKER.md` contract, then `--collect-bounded` and `--finalize`. Run `ingest_open.py --root ROOT --rebuild` first when open-access texts were fetched. The path stays opt-in until it meets the re-adoption bar in [the reversion plan](../docs/plans/single-review-reversion.md): at least 18/20 gold verdicts, a complete bibliography and hyperlink section, measured cost at or below $0.10 and 16 minutes, and no full source text in the main context.

**Source reading.** Read sources in targeted excerpts: use `sourcepack.py --search`, the evidence windows, or `page_map.py`/`open_text_pages.py`, and paste only the matched passage with its locator. Do not dump a whole extracted file into the conversation.

**Reading gate (optional).** Run `reading_gate.py run --batch ROOT --paper paper` when the review must be auditable or the paper has known close-paraphrase risk. If used, adopt every finding or record a rebuttal with the evidence that defeats it in `ROOT/paper/gate-rebuttals.json` as `{"rebuttals": [{"occurrence": "C2", "check": "lost_qualification", "reason": "..."}]}`; then `apply --rebuttals ...` and `check --gate ... --findings ... --rebuttals ...`. The check must pass before rendering when the gate is used.

**Blocked provider request.** If the host rejects a request with a content-moderation error (`Content Exists Risk`, HTTP 400), do not retry the same conversation: every retry replays the transcript and is rejected again. Stop, keep the work root, and resume in a new session from `_work/` and the ledger. The bounded path is the long-term prevention; until it is default, resuming from the work root is the recovery.

**Harness search handoff.** Run `search_plan.py` for every cited unacquired work, execute its queries with the host's `web_search` tool, and write the returned URLs (with titles/authors/years) to a results bundle. Then run `search_acquire.py --root ROOT --results BUNDLE` or `one_paper.py --out ROOT --search-results BUNDLE`; it fetches through the safe public-fetch path and keeps only title/author/year-verified copies. This uses the harness/model search rather than a separate provider key.

After a complete copy is admitted, run `search_apply.py --batch ROOT --paper PID`. If the paper already has findings, it returns `queued_for_review`, writes `_work/<paper>/acquisition-review-queue.json`, and leaves the task unchanged: do not reuse the old findings. Re-review the paper, or use the reappraise skill when only the newly sourced citations changed. If the paper has no findings yet, `search_apply` prepares the admitted copy and rebuilds the task normally.

**Challenge fallback.** A single 202, 401, 403, cookie wall or challenge page is not a completed search. Use the host's `web_search` with the exact title, identifier and an alternate format query; try at least two independent official/repository/legal-mirror results and record each query and outcome. For EU instruments, search the CELEX/ELI identifier and try EUR-Lex's HTML/PDF/ELI routes and the official Publications Office before recording the text as unavailable.

**Rendering a single review.** With a prepared task, record your adjudicated inventory and judgments using the [sibling worker contract](../sourcefidelity-batch/WORKER_CONTRACT_REVIEW.md) output schema and the single-review protocol. Run `scripts/one_paper.py --out REVIEW_ROOT --inventory inventory.json --findings findings.json` with the resolved Python interpreter after any optional reading-gate check passes. Resolve validation errors in the records and rerun. Completion means the command succeeds and `REVIEW_ROOT/paper/` contains `review.md`, `ledger.md` and `summary.json`. In prompt-only mode, write the review and ledger directly from the protocol. Deliver the accession, hyperlink audit and dossier when produced.

**Retrieval cost.** Resolve in two passes: first `resolve_dois.py --no-attempt` to fill the identity cache cheaply, then run it again with attempts — the second pass reads each identity from the cache and only fetches text for works that exist. Timeouts are already short; do not raise them. The accession record is the retrieval log: do not write ad-hoc probes against archive.org, `repository.si.edu`, Google Books or Project MUSE; a blocked host there is a recorded limitation, not a new experiment worth minutes.
